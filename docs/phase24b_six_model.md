# Phase 24B six-model capture

The opt-in command is `python -m analysis.prospective_monitor capture --six-model`. It uses the existing prospective capture lock and snapshot table. It fetches TFF players, fixture evidence and Football-Data match rows once before running variants. The frozen Football-Data rows are embedded in the snapshot payload as `feature_evidence`; the original source values are not changed. The capture result contains a deterministic batch ID, shared input hash, per-variant status, model version and six saved prediction IDs when complete.

Offline replay is `python -m analysis.prospective_monitor replay-six --snapshot-id <id>`. Replay reads only the existing saved snapshot. It does not fetch current players, fixtures or external matches. It returns an incomplete result and no usable six-model prediction set if evidence is absent or one model fails. The CP-SAT optimizer has time limits, so feasible (unproven) selections may be nondeterministic; compare result IDs and objective values rather than claiming byte-identical replay until solver determinism is established.

Variants: baseline_5w, short_form_3w, stable_8w, uniform_xg (40%), position_aware_xg (40%), and rest_days_control (zero weight). The last three use short_form_3w as their common base. The rest control cannot demonstrate a rest feature benefit.

Deadline source is the official TFF fixture API response with its retrieval time. The repository classifies a local capture before that deadline as **locally recorded pre-deadline, not independently verified**. No independent timestamp proof is available, so these batches do not qualify for primary verified prospective evaluation. Current capture also requires a known future deadline; unknown-deadline batch capture remains a gap. Finalized official results are checked by the existing `benchmark_evaluation` engine; missing results are never replaced with zero.

The official fantasy [help page](https://tfffantezilig.com/yardim?lang=en&tab=sss) defines the deadline as the final time for gameweek changes, says the platform displays it in the user's local time, and says points are finalized only after match data and automatic processes complete. The capture uses the API deadline value and UTC retrieval timestamp; a local clock comparison remains insufficient independent proof.

The original form-model benchmark still saves separately in the same capture. A failed six-model replay saves no six-model predictions, but the incomplete batch status is returned by the command rather than stored as a durable batch record. SQLite and PostgreSQL six-model transaction behavior has not been exercised against an isolated PostgreSQL database in this environment. Do not schedule this path as a validated production evaluation workflow yet.
